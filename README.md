## ⚡ What is detour

detour is **our own GPU driver userspace**. Command buffers, state and shader machine code are all generated by detour
itself and submitted **straight through the kernel GPU driver's ioctls**. No Mesa, no Vulkan, no OpenGL, no libdrm in between.

🎯 **The goal:** a shorter path than Mesa. No GL / Vulkan state machine, no guessing in a driver layer: every command and every
state bit is ours.

🪟 **Built for acde:** rasterizing web layers, WebGPU (`navigator.gpu`) and the `<canvas>`
`webgl` / `webgl2` / `webgpu` contexts in every acde window go through detour.

## 🔥 Why it's different

| | |
| --- | --- |
| 🦀 **All Rust** | From the IR to the ioctl. No C driver stack under it. |
| 🧬 **One MLIR for every GPU** | Every vendor's command streams and shader binaries come out of the same [mlirformat](https://github.com/Jabberwocky238/mlirformat) / [mlirpass](https://github.com/Jabberwocky238/mlirpass) pipeline. It is not a compatibility layer. |
| 🎨 **Everything Vulkan can do** | Full 3D graphics and compute, with Vulkan's capabilities as the bar. The interface is our own (the `detour` dialect plus the runtime), not the Vulkan API. |
| ⏱️ **MLIR never runs per frame** | Pipelines are compiled once; each frame only copies a template and fills in addresses: **~17 µs** to record a frame (debug build). |
| 🎯 **Bit-exact or it didn't happen** | Being deployed is not success. Pixels and read-back values are checked one by one, against Mesa, gentool, LLVM or a Rust model. |
| 🛟 **Always draws something** | No supported GPU? It falls back to vello on wgpu (Vulkan). No GPU at all? The CPU draws the pages. |

## 🧬 The pipeline

```text
detour.* (resources, pipelines, render passes) + shaders (func / spirv / gpu)
  ⇒ 🧠 frontend   unify shaders, expand clears, canonicalize / cse
  ⇒ ⚙️ backend    image.kernel / xe3.cmd / xe3.state, register allocation, software scoreboard, addressing
  ⇒ 📦 image      ⇒ kmd trait (xe ioctl)
  ⇒ 🖥️ GPU
```

## 🎮 GPUs

| GPU | Kernel driver | Status |
| --- | --- | --- |
| 🔵 **Intel Xe3** (Panther Lake, PCI 8086:b0a0) | `xe` | ✅ **Main target.** Render, compute, runtime, 2D compositing, blur effects, all running on real hardware |
| 🍎 **Apple M1** (AGX G13) | `asahi` (Asahi Linux) | 🚧 Kernel interface, `agx` dialect, USC encoding and compute written and checked bit by bit against Mesa; not on real hardware yet |
| 🍏 **Apple M3 / M4** (Apple9) | none (Metal binary archive) | 🧪 Compute encoding verified on an M4 |
| 🔴 **AMD RDNA2** (gfx1036) | `amdgpu` | 🚧 PM4, instruction encoding and compute dispatch done and checked against Mesa / `llvm-mc`; not on real hardware yet |
| ⚪ Anything else | | 🛟 `fallback-vulkan`: vello on wgpu |

## 🏆 Proven, bit by bit

| ✔️ Check | Result |
| --- | --- |
| 📦 genxml packing vs Mesa's C packer | **290** entries, bit-identical |
| 🔣 EU encoding vs gentool (`asm -p ptl`) | **67** `xe3.eu` ops bit-identical, including DPAS and LSC 2D block |
| 🧮 Shader math (`math`) | **65,536** operand sets (denormals, ±∞, NaN …) for div, sqrt, fma, floor, min / max, compare + select: **0 errors**, correctly rounded |
| 🔺 Triangles (`triangle`) | four shader styles (func / gpu / spirv / arith): **0** wrong pixels |
| 🌫️ Dual Kawase blur (`frost`) | 13 stacked effects vs a Rust model, byte for byte: **0 errors**; **1.02 ms** GPU per 1200×700 panel |
| 🔢 Compute + integers (`compute`) | 65,536 invocations, 20 kinds of results vs Rust: **0 errors** |
| 🎞️ Runtime (`frames`) | 1000 back-to-back 1920×1080 frames, record p50 **17 µs**, last frame **2.07 M pixels, 0 wrong** |

Full table and conditions: [docs/verification.md](docs/verification.md).

## 🚀 Quick start

```sh
# 🔍 which GPUs are here and how far detour gets on each (-v prints the driver's parameters)
cargo run --features cli,xe3,agx-g13,rdna2 -- devices

# 🧪 no GPU needed: packing vs Mesa, encoding vs gentool, the frontend
cargo test --workspace

# 🔺 needs Xe3: triangles in four shader styles, checked pixel by pixel
cargo run --features xe3 --example triangle

# 🎞️ the runtime: 1000 frames, recording / throughput / latency, checked pixel by pixel
cargo run --features xe3 --example frames

# 🔬 print the lowered MLIR
cargo run --features xe3 --example lower -- crates/intel/driver/examples/triangle/func.mlir

# 🧱 more on Xe3, each checked pixel by pixel
cargo run --features xe3 --example indexed   # indexed draws (u16 / u32, first index, base vertex)
cargo run --features xe3 --example depth     # depth test (compare, write on / off, depth clear)
cargo run --features xe3 --example uniform   # render shaders reading a uniform buffer
cargo run --features xe3 --example mipmap    # mipmaps (level from derivatives)

# 🥊 the same frames / dispatches on Mesa anv and iris, both sides checked pixel by pixel
cargo bench --features xe3 --bench against_vulkan
cargo bench --features xe3 --bench against_opengl

# 🪟 in a window
cargo run -p triangle      # a triangle (read back, shown through softbuffer)
cargo run -p triangle3d    # a spinning 3D triangle
```
