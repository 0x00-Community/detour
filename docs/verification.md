# Development and verification

- This machine (`192.168.100.180`) is Xe3 (8086:b0a0, xe, `/dev/dri/renderD128`, the user is in the render group): run anything that needs the GPU directly.
  Another test machine: Core Ultra 7 356H (Xe3, IP 30.01, 4 Xe cores, 8 SIMD16 EUs each), AgentOS (ackernel 7.2, xe),
  `ac@192.168.33.139` (`ac.local`), `DETOUR_HOST=ac@192.168.33.139 scripts/on-host.sh '<command>'` (rsyncs to the remote `~/detour`, then runs);
  the user must be in the `render` group, rust comes from pacman, there is no `~/.cargo/env`.
- `cargo test --workspace`: front end (three shader styles yield the same module through FRONTEND), xe3 packing against Mesa, EU encoding against gentool, uAPI struct sizes.
- Needing the GPU: `cargo run --features xe3 --example triangle` (four styles, pixel for pixel + pipeline statistics), `--example frames` (runtime: recording / throughput / latency, pixel for pixel), `--example store`, xe's `--example xe-info`.
  Deploying and running does not count as success; only pixels / read-back values matching one by one does.
- mlirformat's release (opt-level 3) build is very slow: a debug build is enough for verification.
- The EU encoding reference tool gentool (Mesa `src/intel/compiler/gen`, `gentool asm|disasm -p ptl`) has to be built from the Mesa tree on Linux:
  `meson setup build -Dtools=intel -Dvulkan-drivers= -Dgallium-drivers= -Dplatforms= -Dglx=disabled -Degl=disabled -Dgles1=disabled
  -Dgles2=disabled -Dopengl=false -Dllvm=disabled -Dintel-elk=false`, `ninja -C build src/intel/compiler/gen/gentool`.
